# 3. Избор на подход (Метод)

---

# a. Какви основни обработки от КЛ са необходими?

- Нормализация на текста (премахване на HTML тагове, пунктуация, малки букви)
- Токенизация и лематизация чрез **Classla**
- POS tagging - филтриране по NOUN, PROPN, ADJ, VERB
- Премахване на стоп-думи (stopwordsiso за български)
- Извличане на признаци: униграми, биграми, глаголи

---

# b. Какви допълнителни алгоритми са приложени?

- **PMI-базирано индуциране на правила** - за всеки клас се избират до 30 "cue" думи с най-висок PMI score (Експ. I, II)
- **Intent/Slot Extraction** - ръчно дефинирани cue думи за извличане на topic, paradigm, direction (Експ. III)
- **TF-IDF + Cosine Similarity** - векторно представяне на лематизиран текст и търсене на подобни задачи (Експ. IV)
- Стратифицирано разделяне train/test (80/20)

# I. Експеримент: Rule-based PMI класификатор

- Използване на PMI-базиран rule-based класификатор върху български текст
- NLP pipeline: Classla (tokenize, POS, lemma) + stopwords филтриране
- Признаци: леми (униграми, биграми), глаголи, key_phrases от анотации
- За всеки клас се индуцират Top-30 правила с положителен PMI score

---

# I. Експеримент - Резултати

| Метрика                    | Стойност                                               |
| -------------------------- | ------------------------------------------------------ |
| Accuracy                   | 0.333 (22/66)                                          |
| Перфектни класове (F1=1.0) | binary_search_tree, linked_list                        |
| Неточни класове (F1=0.0)   | dynamic_programming, priority_queue, stack_queue, tree |

# I. Експеримент - Изводи

- Класове с характерна лексика (BST, linked_list) се разпознават перфектно
- Класове дефинирани чрез техника на решение (DP, stack_queue) нямат лексикални сигнали в условието, за което съответсва F1 = 0
- Висок precision, нисък recall при graph/shortest_path - правилата са точни, но недостатъчни
- Подходът не улавя абстрактни алгоритмични концепции

# II. Експеримент: PMI Cue Extraction със слети класове

- Същият PMI подход, но с **обединени класове** чрез LABEL_MAP (12 → 7 класа)
  - graph_traversal + shortest_path + MST → **graph**
  - binary_search_tree + tree → **tree_structure**
  - linked_list + stack_queue + priority_queue → **linear_structure**
- Оценка чрез **Top-K accuracy** вместо само Top-1
- 31 тестови примера

---

# II. Експеримент - Резултати

| Метрика        | Стойност      |
| -------------- | ------------- |
| Top-1 Accuracy | 0.226 (7/31)  |
| Top-3 Accuracy | 0.645 (20/31) |
| Top-5 Accuracy | 0.903 (28/31) |
| Cue Overlap    | 0.968 (30/31) |

---

# II. Експеримент - Анализ

- Top-1 accuracy е нисък (22.6%), но правилният клас попада в **Top-3 в 64.5%** и в **Top-5 в 90.3%** от случаите
- Cue overlap 96.8% - почти винаги правилният клас получава _някакъв_ score
- Основен проблем: **searching** доминира като Top-1 предсказание за почти всички класове - правилата за searching са твърде общи
- Сливането на класовете намалява броя тестови примери (66 → 31), но не подобрява Top-1

# III. Експеримент: Intent/Slot Extraction

- Ръчно дефинирани **slot правила** с лематизирани cue думи за български
- Извличане на структурирана информация за всяка задача:
  - **topic** (12 класа), **paradigm** (6 типа)
- Оценка на topic slot срещу OpenAI анотации (329 примера, без train/test split)

---

# III. Експеримент - Резултати

| Метрика         | Стойност |
| --------------- | -------- |
| Accuracy        | 0.307    |
| Macro Precision | 0.236    |
| Macro Recall    | 0.196    |
| Macro F1        | 0.186    |

---

# III. Експеримент - Изводи

- Accuracy (30.7%) е сходна с PMI класификатора, но macro F1 (0.186) е по-нисък
- Ръчните cue думи са ограничени - не покриват разнообразието на текстовете
- Предимство: Можем да извлечем допълнителни атрибути

# IV. Експеримент: TF-IDF Similarity Search

- Лематизиран текст - **TF-IDF** вектори (униграми + биграми)
- **Cosine similarity** между всяка задача и останалите
- Leave-one-out оценка: за всяка задача търсим Top-5 най-подобни
- Метрики: P@1, P@3, P@5, MRR, MAP@5

---

# IV. Експеримент - Резултати

| Метрика     | Стойност |
| ----------- | -------- |
| P@1         | 0.511    |
| P@3         | 0.441    |
| P@5         | 0.423    |
| MRR         | 0.614    |
| MAP@5       | 0.587    |
| Общо заявки | 329      |

---

# IV. Експеримент - Изводи

- P@1 = 51.1% - значително подобрение спрямо rule-based подходите (~30%)
- MRR = 0.614 - правилният клас обикновено е в първите 2 резултата
- BST и linked_list отново водят (>84%) - силен лексикален сигнал
- DP (36.8%) и hash_table (21.9%) остават трудни - условията им не споделят уникална лексика
- TF-IDF улавя по-добре контекста от ръчни cue думи, но все още е ограничен от bag-of-words представянето
